# Declaration for the per-user `litellm` application (LiteLLM AI gateway).
# Parsed by modules/apps.sh: `key = value`, one per line.
#
# Role on this machine: the fleet's inference gateway (see
# docs/runbooks/fleet-host.md, "Inference gateway"). It holds the one real
# upstream credential and hands out per-sandbox keys. It is a long-running
# service, not a command: it runs as the `litellm.service` user unit
# (chezmoi-managed; ExecStart on the standard launcher, which supplies the
# bind address, config and EnvironmentFile the service needs). A bare
# `litellm` invocation starts an unconfigured proxy — apps.sh creates the
# launcher for every app as the smoke-test entry point, but hand-running
# this one is not the supported path.
#
# Provenance policy:
#   LiteLLM is a Python project; its canonical channel is PyPI, and PyPI
#   publishes no signing for these artifacts (verified 2026-10-14: has_sig
#   false on the release files). The npm package named `litellm` is an
#   unrelated project — do not confuse the two.
#   The artifact below is therefore a VENDOR TREE built from the pinned
#   package, and its `sha256` is a LOCAL RECOVERY ANCHOR in chrome.txt's
#   sense: it detects corruption or substitution since the anchor date, not
#   independent publisher verification. Independence comes from the
#   dependency lock packages/apps/litellm.lock (362 entries, each pinned to
#   the exact PyPI release file it resolves to, hash-checked by uv at
#   install; regenerate + diff on every bump).
#   The gateway binds localhost, so the anchor's exposure surface is local
#   file replacement — the same trust base as every other app here.
#
#   Build recipe (rebuild the artifact for a version bump):
#     1. lock:   cd <tmp>; pyproject.toml with
#                  dependencies = ["litellm[proxy]==<ver>"], requires-python >=3.13
#                uv pip compile --python-version 3.13 --python-platform linux \
#                  pyproject.toml -o <new lock>   (replace packages/apps/
#                  litellm.lock — committed dependency lock, NOT *.txt:
#                  *.txt in that dir are declarations)
#     2. install: uv venv --seed -p 3.13 v
#                UV_NO_CACHE=1 uv pip install --python v/bin/python \
#                  --no-cache -r litellm-<ver>.lock.txt
#     2b. de-absolutize: the venv is NOT relocatable — every console script
#        in v/bin embeds the build-dir interpreter path in its shebang, and
#        the activate scripts embed it as VIRTUAL_ENV. Rewrite build refs to
#        the final install path BEFORE packing:
#          grep -rl "<build-dir>/v" v/bin | xargs sed -i \
#            's|<build-dir>/v|'"$HOME"'/.local/apps/litellm/<ver>|g'
#        (bin/python is a symlink to the mise python; the venv only needs
#        that symlink to resolve — the baked path is the version dir, which
#        matches apps.sh's install location exactly.)
#     3. pack:   tar --sort=name --mtime='UTC <date>' --owner=0 --group=0 \
#                  --numeric-owner --exclude='__pycache__' --exclude='*.pyc' \
#                  -czf litellm-vendor-<ver>.tgz -C <build-dir> v
#                (mv the extracted tree to `litellm/` before install, or use
#                prefix = v; the committed tarball top-level is `v`)
#     4. place litellm-vendor-<ver>.tgz in ~/.cache/workstation/apps/,
#        update version/archive/sha256 here (and the lock in source/ when
#        the lock changed), rerun: bash modules/apps.sh litellm
#   The tree is NOT relocatable in the interpreter sense: console-script
#   shebangs are absolute (see step 2b). It survived the initial 2026-10-14
#   install only because the build dir (/tmp/opencode/ltx) still existed
#   when the launcher ran; when /tmp was cleared the launcher died with
#   ENOENT (systemd 203/EXEC) — fixed and re-anchored 2026-10-15.
#
#   Recovery anchors, initial declaration 2026-10-14 (all for 1.105.1):
#     sdist sha256   f1a274db0b2bcc78… (see source lock header note)
#     wheel sha256   f3d743c2d274c6537f7341213607c927c486676012a9d94412a8a8ccbe2f51f1
#                    (litellm-1.105.1-cp310-abi3-manylinux_2_28_x86_64.whl)
#     lock sha256    288e6404bac72f5b08e293e92a21fbc2834b6aeca1bef195d456f16f16d3e6ab
#     vendor sha256  ce1940fd26aef1e25c90dcb25cc65ba4604d3609b6965ac493e64a993b396368
#                    (superseded: that tarball's scripts point at the
#                    transitory build dir — do not reinstall from it)
#   Re-anchored 2026-10-15 after the step-2b shebang rewrite (same lock,
#   same code; only v/bin paths differ):
#     vendor sha256  c01a4c29ec4cb376ca84d66949b5997d0eb7e441a122e2a0283c0dde4287aa2a
#   Rollback: restore version/archive/sha256 to the anchors above; the
#   archive stays in the cache.

# Functional check: the vendored interpreter must import the proxy server
# module (exercises the C extensions and the full dependency closure, not
# just the launcher), and the CLI must report the declared version.
# NOTE: values here are raw — declaration syntax adds no shell quoting
# (every sibling declaration is unquoted), so shell expansion inside the
# value must be parenthesized: $APP is the launcher symlink, its target
# ends in /<version>/bin/litellm, and ${...} derives the sibling python.
smoke = true
